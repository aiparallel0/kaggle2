\section{F1-Destroying Bugs and Fixes}
\label{sec:bugs}

We identified the following thirteen implementation bugs during
development.  Each is a silent failure: the code runs to completion and
the loss decreases, but the final F1 is drastically degraded.  All are
guarded in source; the guards are cited inline.

\begin{enumerate}

\item \textbf{lm\_head safetensors deduplication} (F1\,$\approx$\,0.42).
  Safetensors deduplicates tied weights on save and drops the
  \texttt{lm\_head} tensor.  On reload the head is re-tied at the
  wrong dimension, yielding nonsense output.
  \emph{Guard}: set \texttt{tie\_word\_embeddings=False} before
  saving and clone the head weights explicitly.

\item \textbf{Wrong decoder\_start\_token\_id} (F1\,=\,0.00).
  Passing the tokeniser prompt as a string to \texttt{convert\_tokens\_to\_ids}
  returns the ID of the first character (\texttt{<}) rather than the
  special token.  \emph{Guard}: always use the list form
  \texttt{processor.tokenizer.convert\_tokens\_to\_ids(["<task\_start>"])}.

\item \textbf{token2json returns a list on CORD-style prompts}
  (F1\,$\approx$\,0.008).
  The DONUT helper \texttt{token2json} wraps output in a list when it
  detects multi-page structure.  \emph{Guard}: if the return value is
  a list, merge pages into a single dict before field extraction.

\item \textbf{fp16 loss overflow} (loss\,=\,NaN).
  fp16's dynamic range is insufficient for the DONUT cross-entropy
  loss on long sequences.  \emph{Guard}: use bf16 on Ampere\,+
  GPUs; use fp16 only with \texttt{max\_grad\_norm}\,$>$\,0
  (the config loader enforces this invariant at load time).

\item \textbf{YOLO imgsz mismatch at inference} (0\,\% detection).
  YOLOv8 inference defaults to \texttt{imgsz=640}; if training
  used a different size, the model's anchor priors are scaled to the
  wrong resolution and no boxes are produced.  \emph{Guard}: always
  pass \texttt{imgsz} explicitly to both \texttt{model.train()} and
  \texttt{model.predict()}, and assert train/eval parity via
  \texttt{pipeline\_meta.json}
  (\texttt{parity\_ok}\,=\,\VAR{parity_ok}).

\item \textbf{TrOCR undertrained} (all-empty predictions).
  Validation loss at epoch~1 is $\approx$9.1, far above the
  convergence threshold.  Predictions are empty strings, propagating
  zero-length texts to the assigner.  \emph{Guard}: require at least
  5 epochs; the config loader raises \texttt{TrainError} if
  \texttt{epochs\_trocr}\,$<$\,5.

\item \textbf{Validation equals test leakage}.
  An earlier data-split implementation drew val and test from the same
  shuffled pool, causing the same images to appear in both.
  \emph{Guard}: the split is computed once, persisted to
  \texttt{results/split.json}, and checked for overlap at load time.

\item \textbf{YOLO project-path collision} (\texttt{ultralytics}\,$\geq$\,8.3).
  Ultralytics~8.3 changed the default \texttt{project} directory to an
  absolute path that collides with a pre-existing \texttt{runs/} tree,
  causing \texttt{FileExistsError} on re-runs.  \emph{Guard}: always
  pass an explicit \texttt{project} and \texttt{name} to
  \texttt{model.train()}.

\item \textbf{Stale generation\_config on reload} (eval\_F1\,$\equiv$\,0
  with healthy eval\_loss).
  \texttt{Seq2SeqTrainer(predict\_with\_generate=True)} reads
  \texttt{model.generation\_config}, which is snapshotted at
  \texttt{from\_pretrained} time --- \emph{not} the live overrides we
  place on \texttt{model.config}.  So \texttt{decoder\_start\_token\_id}
  falls back to the base mBART \texttt{<s>},
  \texttt{token2json} receives a token stream with no recognisable
  field tags, and returns \texttt{\{\}}; per-field F1 is a clean zero
  while the cross-entropy loss decreases normally.  This is the single
  most expensive silent bug in the codebase.
  \emph{Guard}: after loading a checkpoint, mirror the relevant ids
  (\texttt{decoder\_start\_token\_id}, \texttt{pad\_token\_id},
  \texttt{eos\_token\_id}, \texttt{max\_new\_tokens}) from
  \texttt{model.config} into \texttt{model.generation\_config}
  before the first \texttt{trainer.evaluate()} or
  \texttt{model.generate()} call.

\item \textbf{tie\_word\_embeddings=False subtlety}.
  Setting \texttt{tie\_word\_embeddings=False} (the Bug~1 fix) creates
  an independent \texttt{lm\_head} but also means that subsequent
  \texttt{resize\_token\_embeddings()} calls no longer automatically
  resize the output projection.  If new task tokens are added after
  this flag is set, \texttt{lm\_head} must be resized and
  re-initialised explicitly.  \emph{Guard}: call
  \texttt{model.lm\_head = torch.nn.Linear(...)} after any token
  vocabulary expansion that follows the \texttt{tie\_word\_embeddings}
  flag change.

\item \textbf{\texttt{num\_items\_in\_batch} kwargs leak}
  (\texttt{TypeError} on first batch).
  \texttt{transformers}\,$\geq$\,4.48 injects
  \texttt{num\_items\_in\_batch} into the training step's
  \texttt{**kwargs}, which leaks through
  \texttt{VisionEncoderDecoderModel.forward} into
  \texttt{SwinModel.forward}, which accepts no \texttt{**kwargs}, and
  the first forward pass raises.  \emph{Guard}:
  \texttt{donut\_train.py} sets
  \texttt{model.accepts\_loss\_kwargs\,=\,False} on the wrapper so
  \texttt{Trainer} stops injecting the kwarg at all.

\item \textbf{Outer \texttt{<s\_sroie>} wrapper flattening}
  (per-field F1\,=\,0 with healthy eval\_loss).
  Our training labels wrap each receipt in
  \texttt{<s\_sroie>...</s\_sroie>}, and the same tag doubles as the
  task start/EOS token.  HF's \texttt{token2json} therefore parses the
  root tag as a dict key, returning
  \texttt{\{"sroie": \{"company": \ldots, \ldots\}\}};
  \texttt{compute\_metrics} then sees ``missing keys'' for every field
  and scores F1\,=\,0 while the cross-entropy loss descends normally.
  \emph{Guard}:
  \texttt{donut\_parse.\_flatten\_token2json} recursively unwraps any
  single-key root dict whose key matches the task tag.

\item \textbf{Warmup-steps-vs-ratio precedence}.
  Hugging Face's \texttt{Trainer} consults \texttt{warmup\_steps} first
  and uses it whenever it is $>$\,0, silently overriding
  \texttt{warmup\_ratio}.  A non-zero \texttt{warmup\_steps} left in a
  config therefore nullifies the ratio we meant to apply.
  \emph{Guard}: \texttt{donut\_train.py} forces
  \texttt{warmup\_steps\,=\,0} whenever
  \texttt{warmup\_ratio\,$>$\,0}, restoring the intended behaviour.

\end{enumerate}
