\title{Can Regex Beat DONUT on Receipts?
       A Three-Arm 500/63/63 SROIE Study of
       End-to-End vs.\@ Pipeline KIE}

\author{\IEEEauthorblockN{Anonymous}
\IEEEauthorblockA{Under review}}

\maketitle

\begin{IEEEkeywords}
Key Information Extraction, SROIE, document understanding,
rule-based baselines, ablation, reproducibility.
\end{IEEEkeywords}

\begin{abstract}
We compare three Key Information Extraction (KIE) arms on the SROIE
receipt benchmark under a fixed 500\,/\,63\,/\,63
train\,/\,val\,/\,test split drawn from the 626 official ICDAR-2019
training receipts: (i) DONUT, an end-to-end sequence-to-sequence
model ($\approx$200\,M parameters); (ii) a YOLO+TrOCR+\emph{regex}
pipeline without a learned assigner head; and (iii) a GT-OCR
$+$\,regex baseline that bypasses YOLO+TrOCR entirely by feeding
SROIE ground-truth box text into the same regex extractor.  With
$n_{\text{trials}}=\VAR{n_trials}$ DONUT reaches a global
token-F1 of \VAR{donut_f1:mean_std_pct1}, the YOLO+TrOCR+regex
pipeline reaches \VAR{pipeline_f1:mean_std_pct1}, and the GT-OCR
baseline reaches \VAR{gtocr_rulebased_f1:mean_std_pct1} —
isolating how much of pipeline performance is attributable to the
deterministic regex layer versus the upstream OCR stack.  The
$\Delta$F1 between DONUT and the regex-only pipeline is
\VAR{f1_gap} (paired-bootstrap 95\% CI \VAR{delta_f1_ci_lo}--%
\VAR{delta_f1_ci_hi}; McNemar $p=$\VAR{mcnemar_p:p}).  We catalogue
13 silent F1-destroying implementation bugs the project has guarded
against, and publish full GPU telemetry alongside every reported
number.  Because the test split is internal it is \emph{not}
comparable to the official SROIE Task-3 leaderboard; for that
comparison see the advanced (canonical-test) variant of this work.
\end{abstract}
